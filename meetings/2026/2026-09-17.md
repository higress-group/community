## Notes

### Community updates

- Higress submitted its CNCF Incubation application on September 4. The
  application, technical review, and governance review are awaiting CNCF
  triage or reviewer assignment. Adopter questionnaires have been submitted
  for Ant Digital, Kuaishou, Trip.com Group, Vipshop, and Labring/Sealos.
- Higress is listed as an implementation by both Kubernetes Gateway API and
  Gateway API Inference Extension.
- The meeting reviewed the Envoy 1.36.10 upgrade, recent MCP protocol
  compatibility work, and fixes for streaming model responses split across
  network frames. Follow-up questions remain around Envoy API and HTTP/2
  behavior when upgrading from 1.27-era deployments.
- HiRoute, an adaptive model-routing runtime for long-running agents, has a
  public repository and is planned for an open-source announcement around the
  Apsara Conference.

### Built-in endpoint picker

- The built-in Gateway API Inference Extension endpoint picker removes the
  external EPP hop while retaining health filtering and load-aware endpoint
  selection. Its default score combines queued requests, KV-cache utilization,
  approximate prefix-cache hits, and gateway-local in-flight requests.
- In the recorded 40-concurrency benchmark, the built-in picker reduced mean
  time to first token from 311.63 ms with round-robin to 214.42 ms and raised
  token throughput from 489.71 to 565.65 tokens per second.
- Results were workload-dependent. At concurrency 20, the external EPP had a
  lower mean time to first token and a higher prefix-cache hit rate than the
  built-in picker. The source notes also record a controlled single-node
  congestion test in which both load-aware approaches avoided the congested
  node.
- External EPP and the built-in picker remain alternative configurations.
  Existing HTTPRoutes can target separate InferencePools when both modes are
  needed.

### Agent and AI gateway discussion

- The current A2A work provides the protocol-proxy foundation: JSON-RPC and
  SSE forwarding, protocol validation, trusted metadata extraction, Agent Card
  validation and address rewriting, and `hgctl agent add --type a2a` onboarding.
- Observability, consumer authentication, task or node affinity, and broader
  Agent-platform integration remain follow-up work rather than part of the
  initial A2A proxy change.
- The discussion distinguished model affinity within an Agent loop, Responses
  deployment affinity, and A2A task-to-Pod affinity as separate requirements.
- Sandbox sessions, HiMarket, a unified AI control plane, MCP long-running
  tasks, exact vLLM cache awareness, AI cache and session handling, structured
  output, and inference scheduling configuration will continue in their
  linked proposals and pull requests.

### Additional proposals

- The meeting reviewed MCP automatic protocol negotiation and security,
  observability, workload identity for Bedrock and Vertex, external
  authorization enhancements, and plugin artifact and manifest validation.
- Independently actionable work included Qdrant support, OpenAI-compatible
  vision models, automatic-routing inputs, Qwen3Guard streaming responses, MCP
  incremental updates, separate log and metric controls, and developer tools.
- The source notes did not record a final priority order for these proposals.

## Decisions

- Continue tracking the CNCF Incubation application and its supporting reviews
  through the linked public CNCF artifacts.
- Treat the external EPP and built-in endpoint picker as selectable deployment
  alternatives. Follow up on release and trial feedback instead of reopening
  the completed decision to implement the built-in picker.
- Keep the initial A2A implementation focused on the protocol-proxy foundation;
  track observability, authentication, and affinity as follow-up work.
- No final next-version priority was recorded for the other proposals reviewed
  during this meeting.
